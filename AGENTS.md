# AGENTS.md

Instructions for coding agents working in the Tessera repository or consuming Tessera in another project.

## What Tessera is

An original, copy-paste React UI kit built on Tailwind CSS v4 and CSS variables. It is inspired by shadcn's ownership model but is not a clone. Warm editorial design, custom tile theme glyphs, no runtime package.

- Repository: `github:dhirajaryaa/tessera`
- Docs: `https://dhirajaryaa.github.io/tessera`
- Components: 14
- Themes: Paper, Ink, Moss, plus an Auto system preference
- Runtime dependencies: none. `clsx` and `tailwind-merge` are build-time helpers for `cn()`.

## Hard rules

1. **Tokens only.** Every colour, border, surface, radius, font and shadow comes from a `--ts-*` variable. Never use palette classes such as `bg-zinc-900`, `text-blue-600` or `border-neutral-300`.
2. **No runtime UI libraries.** Do not install or import Radix, Headless UI, React Aria or CVA. Use native elements and React state.
3. **No wrapper library.** Components are copied into the project and edited there. Do not build a second abstraction layer over them.
4. **Small radius.** Default `--ts-radius` is `8px`. Do not turn buttons, inputs, cards or dialogs into pills. Circles are for avatars and status dots.
5. **One accent per screen.** `--ts-accent` is for the primary action, active indicators and focus rings. It is not decoration.
6. **Custom glyphs.** The theme switcher uses four tile glyphs for Paper, Ink, Moss and Auto. Never replace them with sun and moon icons.
7. **Accessibility is not optional.** Keyboard access, visible focus, correct ARIA states, Escape and focus restore are part of the component.

## Working in the repository

Run site commands from `site/`:

```bash
npm install          # first time
npm run sync         # copy registry into the site
npm run typecheck    # tsc --noEmit
npm run build        # static Next.js export to site/out
npm run dev          # local docs site
```

`npm run build` runs `sync` first through `prebuild`. The generated copies under `site/components/tessera/`, `site/lib/utils.ts` and `site/styles/tessera.css` are gitignored. Never edit them directly.

### Adding a component

1. Write `registry/tessera/<name>.tsx`. Named exports, kebab-case file.
2. Add an entry to `registry.json` with `name`, `title`, `description`, `category`, `files`, `registryDependencies`, `dependencies`.
3. Add the slug and summary to `site/lib/components.ts`.
4. Add the full doc object (code, anatomy, props, use, avoid, a11y) to `site/lib/component-docs.ts`. The docs page throws at build time if an entry is missing.
5. Add a live demo case to `site/components/docs/demos.tsx`.
6. If the component needs a new dependency, add it to `registry.json`, but prefer native HTML.
7. Run sync, typecheck and build. Open the page at desktop and mobile widths.

### Component style

- Forward refs for form controls and buttons.
- Accept and spread native HTML attributes.
- Use `cn()` from `@/lib/utils`.
- Use tokens through Tailwind utilities where possible: `bg-ts-surface`, `text-ts-ink`, `border-ts-line`, `rounded-ts`, `font-ts-mono`, `shadow-ts`.
- Focus ring pattern: `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ts-ink`.
- Keep transitions to 150 to 250ms and respect `prefers-reduced-motion`.
- Comments explain decisions, not syntax.

### Docs and voice

- Plain, specific, confident, dry. Short sentences.
- No em dashes in body copy.
- Do not use `seamless`, `effortless`, `elevate`, `unleash`, `robust`, `powerful`, `delve`, `game-changer` or `cutting-edge`.
- No invented metrics, download counts or testimonials.
- Say what a part is for and when to leave it out.

## Consuming Tessera in another project

### Prerequisites

- React 18 or 19, TypeScript, Tailwind CSS v4.
- `@/*` path alias pointing at the project root or `src`.
- `clsx` and `tailwind-merge` (the CLI checks and reports).

### Install

```bash
npx github:dhirajaryaa/tessera@main init
npx github:dhirajaryaa/tessera@main add button dialog
npx github:dhirajaryaa/tessera@main list
```

Init does four things:

1. Writes or updates `tessera.json` with `componentsDir`, `libDir`, `css` and `themeFile`.
2. Copies `tessera.css` (the `--ts-*` token sheet) next to the global CSS.
3. Copies `utils.ts` with `cn()` and a small controlled-state helper.
4. Adds `@import "./tessera.css";` after the Tailwind import.

The default import order is:

```css
@import "tailwindcss";
@import "./tessera.css";
```

Useful flags: `--yes`, `--force`, `--overwrite`, `--cwd <path>`, `--components <path>`, `--lib <path>`, `--css <path>`, `--json`, `--no-color`.

### Theme contract

Set a default theme on the root:

```html
<html lang="en" data-theme="paper">
```

Allowed values: `paper`, `ink`, `moss`. The provider stores the preference under `tessera-theme` and resolves `system` to Paper or Ink from the OS.

Optional provider:

```tsx
import { ThemeProvider } from "@/components/tessera/theme";
import { ThemeSwitcher } from "@/components/tessera/theme-switcher";

<ThemeProvider defaultPreference="system">
  <ThemeSwitcher />
  {children}
</ThemeProvider>
```

Add the blocking theme script described in `docs/theming.md` to avoid a first-paint flash.

### API quick reference

```tsx
<Button variant="solid" size="md" loading={false} />

<Badge tone="success" dot>Active</Badge>

<Field label="Email" htmlFor="email" hint="Receipts only." error={undefined}>
  <Input id="email" type="email" placeholder="you@studio.example" />
</Field>

<Textarea id="note" rows={4} />

<Field label="Plan" htmlFor="plan">
  <Select id="plan" defaultValue="studio">
    <option value="studio">Studio</option>
  </Select>
</Field>

<Checkbox label="Email me a receipt" description="One message." defaultChecked />
<Switch label="Weekly digest" checked={on} onCheckedChange={setOn} />

<Card>
  <CardHeader>
    <CardTitle>Studio</CardTitle>
    <CardDescription>Six seats.</CardDescription>
  </CardHeader>
  <CardContent>...</CardContent>
  <CardFooter>...</CardFooter>
</Card>

<Tabs defaultValue="general">
  <TabsList aria-label="Profile sections">
    <TabsTrigger value="general">General</TabsTrigger>
  </TabsList>
  <TabsContent value="general">...</TabsContent>
</Tabs>

<Dialog
  title="Invite a teammate"
  description="They will get a link."
  trigger={<Button>Invite</Button>}
  footer={<DialogClose>Cancel</DialogClose>}
>
  ...
</Dialog>

<Accordion type="single" collapsible defaultValue="one">
  <AccordionItem value="one">
    <AccordionTrigger>Question</AccordionTrigger>
    <AccordionContent>Answer</AccordionContent>
  </AccordionItem>
</Accordion>

<Avatar alt="Mira Sol" fallback="MS" size="md" />
<AvatarGroup>...</AvatarGroup>

<ThemeSwitcher variant="menu" align="right" />
<ThemeSwitcher variant="rail" />
```

Common generated-code mistakes:

- `variant="primary"` is wrong. The default is `solid`; the variants are `solid`, `soft`, `outline`, `ghost`, `link`.
- Badge uses `tone`, not `variant`.
- Input has no `label` prop. Wrap it in `Field`.
- Select takes `<option>` children, not an `options` array.
- Tabs, accordion, dialog and toast are the compound shapes above, not shadcn's trigger/content API.

## Verification checklist

- `npm run sync`, `npm run typecheck` and `npm run build` pass.
- Every colour comes from a token. Search for `bg-zinc`, `text-blue`, `border-gray`.
- Keyboard: Tab, Enter, Space, arrows, Home, End, Escape.
- Focus is visible in Paper, Ink and Moss.
- Dialog restores focus to its trigger.
- Tabs and accordion report correct ARIA state.
- No new runtime dependency.
- Copy is specific and free of filler.
